7 Domain Failure Patterns — Memory Chain → Ask → Mitigate

1 · Infrastructure

Machine → Disk → Network → Power → Region → Load

Compute + Storage + Network + Power + Environment

  • Is the machine alive?
  • Is disk readable/writable?
  • Is the network reachable?
  • Is power / AZ healthy?
  • Can it handle current load?

Mitigation Pattern

1. Health check + auto-heal (recover) 2. Replication + failover (survive) 3. Autoscaling (handle load) 4. Multi-AZ / multi-region (redundancy) 5. Backup + restore (last resort)

2 · Network

Connectivity → Latency → Routing → Resolution → Security

partition · latency · routing · DNS · TLS

  • Can I reach it? (partition / DNS)
  • Is it slow? (latency / packet loss)
  • Am I at the right place? (routing / LB)
  • Can I resolve the name? (DNS)
  • Is something blocking it? (security / TLS)

Mitigation Pattern

1. Retry with backoff (transient) 2. Timeout + fail fast (latency) 3. Circuit breaker (persistent) 4. Cache / fallback (serve something) 5. Load balance (route properly)

3 · Application / Service

Down → Slow → Exhausted → Blocked → Dependency → Deploy

crash · latency · CPU/mem/threads · deadlock

  • Is the service down? (crash)
  • Is it slow? (latency spike)
  • Is it overloaded? (CPU/mem/threads)
  • Is it blocked? (deadlock / lock)
  • Is it broken by dependency?
  • Is it broken by a deploy?

Mitigation Pattern

1. Restart (recover from crash) 2. Scale (handle load) 3. Retry (transient failure) 4. Cache (reduce dependency) 5. Isolate (circuit breaker / rate limit)

4 · Data Consistency

Missing → Duplicate → Stale → Out-of-Order → Conflict → Partial

ordering · duplication · missing · stale · conflicts

  • Can data be lost? (durability)
  • Can it be duplicated? (idempotency)
  • Can it be stale? (consistency model)
  • Can it arrive out of order? (ordering)
  • Can it be partially written? (transactions)
  • Can it conflict? (concurrency)

Mitigation Pattern

1. Idempotency → no duplicates 2. Transactions / Saga → no partial state 3. Ordering → no out-of-order events 4. Consistency model → no stale reads 5. Reconciliation → fix mismatches

5 · Load / Traffic

Too Much → Uneven → Bursty → Repeated → Slow Processing

spike · hotspot · retry storm · queue backlog · cascade

  • Can traffic increase suddenly?
  • Is traffic distributed unevenly?
  • Do retries multiply the load?
  • Does slow processing cause backlog?
  • Can one failure cascade to others?

Mitigation Pattern

1. Scale (autoscale / replicas) 2. Throttle (rate limit / backpressure) 3. Buffer (queues / async) 4. Cache (reduce work per request) 5. Isolate (circuit breaker / bulkhead)

6 · Dependency

Down → Slow → Partial → Incorrect → Overloaded → Incompatible

unavailable · timeout · wrong data · version mismatch

  • Is the dependency unavailable?
  • Is it slow / timing out?
  • Is it partially failing?
  • Is it returning wrong data?
  • Is it overloaded / incompatible?

Mitigation Pattern

1. Retry (transient failures) 2. Timeout (avoid blocking forever) 3. Circuit breaker (stop bad calls) 4. Fallback (degraded response) 5. Decouple (async / caching)

7 · Distributed System

Partition → Coordination → Replication → Ordering → Time → Tx

split brain · replica lag · duplicates · clock skew · Saga

  • Can nodes communicate? (partition)
  • Can they agree? (consensus)
  • Is data same everywhere? (replication)
  • Are events in order? (ordering)
  • Is time consistent? (clock skew)
  • Is workflow complete? (transaction)

Mitigation Pattern

1. Consensus (Raft/Paxos) → coordinate 2. Quorum → consistent reads/writes 3. Idempotency → handle duplicates 4. Ordering → event correctness 5. Saga / reconciliation → recovery

Thread exhaustion      →    Isolate + Async        →    bulkhead · non-blocking IO
Network partition      →    Fail closed + Retry    →    circuit breaker · quorum
DNS failure            →    Cache + Fallback       →    DNS TTL · local resolve cache
Lost write             →    Durability + WAL       →    fsync · replicated WAL
Duplicate processing   →    Idempotency            →    idempotency key · dedup store
Stale read             →    Consistency model      →    leader read · quorum read
Partial write          →    Atomicity              →    transaction · Saga + compensation
Dep outage             →    Fallback + Decouple    →    cache · async · circuit breaker
Dep slow               →    Timeout + Fail fast    →    per-dep timeout · bulkhead
Split brain            →    Consensus + Fence      →    Raft · epoch fencing · STONITH
Replication lag        →    Quorum + Routing       →    quorum read · route to primary
Clock skew             →    Logical time           →    Lamport clocks · HLC · fencing token

Detection Signals — What to Monitor

Latency (P99)    → slow / backpressure
Error rate       → failure / dependency
Queue depth      → backlog / consumer lag
CPU / Memory     → saturation / OOM
Cache hit ratio  → stampede / cold start
Replica lag      → consistency risk
Connection pool  → exhaustion
Election events  → coordination instability

Interview Answer Skeleton

"First I identify the domain:
  infra / network / app / data / load / dep / dist

Then I ask my memory chain question for that domain.

Then I apply mitigations in order:
  detect → retry → timeout → circuit breaker
  → cache/fallback → scale → isolate

Then I discuss trade-offs."
