NAT
1. NAT — Network Address Translation

NAT translates private IP addresses into public IP addresses, allowing private networks to communicate with external networks.

Private: 192.168.1.10:56000 ↓ NAT Gateway Public: 203.0.113.5:40123 ↓ Internet NAT maintains a connection tracking table mapping internal (IP:port) → external (IP:port).

Why NAT Exists:

  • Conserves IPv4 addresses
  • Hides internal network topology
  • Allows private subnets to access the Internet
  • Supports multi-tenant cloud environments
TypePurposeExample
SNATTranslate source IPOutbound Internet access
DNATTranslate destination IPPublic LB → private service
PATShare one public IP via different portsHome routers
NAT64IPv6 ↔ IPv4 translationDual-stack networks

Common NAT Issues:

ProblemCause
Idle connections dropNAT idle timeout expires
Port exhaustionToo many outbound connections
Hard-to-debug networkingAddress translation hides original endpoints
Connection tracking overflowLarge fan-out traffic
Staff Engineer Insights:
  • Use connection pooling to reduce connection churn against NAT
  • Tune Keep-Alive below NAT idle timeout (typically <30–60 s)
  • Scale NAT gateways for high outbound traffic
  • Monitor connection tracking table utilization
FIREWALLS
2. Firewalls

A firewall enforces security policies by allowing or blocking traffic based on predefined rules.

Packet Arrives → Match Rule → ALLOW | DROP | REJECT
TypeDescription
StatelessEvaluates each packet independently — no connection tracking
StatefulTracks connection state; allows return traffic automatically
NGFWDeep packet inspection + application-layer awareness
WAFProtects HTTP/HTTPS apps — inspects Layer 7 content (SQL injection, XSS, etc.)

Common rule match criteria: Source IP · Destination IP · Port · Protocol · TCP flags · Connection state

Example — allow HTTPS only: TCP dst-port 443 → ALLOW Everything else → DROP
Staff Engineer Insights — Use firewalls to:
  • Isolate network tiers (Internet-facing, app tier, DB tier)
  • Enforce least privilege between services
  • Control east-west traffic inside a VPC/cluster
  • Restrict database access to application subnets only
  • Use WAF for Internet-facing APIs to stop OWASP Top 10 attacks
PROXIES
3. Proxies

A proxy sits between clients and servers, forwarding requests on behalf of one side. It can route traffic, cache responses, terminate TLS, authenticate users, rate limit, and log requests.

Forward Proxy
Client ↓ Proxy ↓ Internet

Outbound traffic control, corporate filtering.

Reverse Proxy
Client ↓ Reverse Proxy ↓ Backends

Used by nearly every production app. NGINXEnvoyHAProxy

Service Mesh Proxy
Service ↓ Sidecar ↓ Network

mTLS, retries, tracing, routing. EnvoyIstio

AdvantageTrade-off
Better security (TLS offload, auth)Additional network hop
Centralized policiesMore infrastructure to manage
Easier TLS certificate managementPotential single point of failure
Improved observability (access logs, metrics)Added latency (1–5 ms typical)
Staff Engineer Insights:
  • Reuse upstream connections via proxy connection pools to avoid handshake storms
  • Terminate TLS at trusted proxy layers — don't re-encrypt unnecessarily
  • Deploy multiple proxy instances with health checks to eliminate single points of failure
  • Use sidecar proxies (Envoy/Istio) for zero-trust mTLS between microservices
PACKET FILTERING
4. Packet Filtering

Packet filtering examines packet headers and decides whether to allow or block traffic. It runs at the kernel level — extremely fast with very low overhead.

Typically filters on: Source IP · Destination IP · Port · Protocol · Connection state

Rule example: TCP dst-port 22 → ALLOW (SSH) Everything else → DROP

Where it runs:

iptables nftables eBPF Cloud Security Groups K8s Network Policies

✅ Advantages

  • Very fast — kernel-level enforcement
  • Low overhead
  • Strong first line of defense

⚠️ Limitations

  • Cannot inspect encrypted payloads
  • Limited application-layer awareness
  • Large rule sets become hard to manage
Packet filtering is best for: host protection, network segmentation, microsegmentation, and early rejection of malicious traffic before it reaches application layers.

STAFF ENGINEER THINKING
Junior → Senior → Staff Progression
LevelThinking Pattern
Junior "I opened port 443 in the firewall. The service is reachable now."
Senior "I configure Security Groups to allow only necessary ports, use a reverse proxy for TLS termination, and put databases in private subnets behind NAT."
Staff "I design defense-in-depth: NAT for private networking with connection pooling and keep-alive tuned below NAT timeout; stateful firewalls + WAF at the perimeter; reverse proxies for TLS offload, routing, caching, and rate limiting; packet filtering at the host/pod level via iptables or eBPF; and service mesh mTLS for zero-trust east-west security. I instrument each layer with metrics and logs so I can distinguish 'blocked by firewall' from 'dropped by NAT' from 'proxy overloaded' during incidents."
Key Takeaways:
  • NAT enables private networking and IPv4 conservation but introduces connection tracking, idle timeouts, and potential port exhaustion — requiring careful keep-alive and pooling strategies.
  • Firewalls enforce security boundaries using least-privilege policies; stateful firewalls track connection state to simplify secure communication.
  • Proxies provide routing, TLS termination, caching, authentication, rate limiting, and observability — central to modern API gateways, CDNs, and service meshes.
  • Packet filtering is the lightweight, kernel-level foundation for network security, efficiently allowing or denying traffic based on packet metadata.
  • In system design interviews, explain how these components work together, discuss their latency and operational trade-offs, and describe how you monitor, tune, and troubleshoot them in production.
