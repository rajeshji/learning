Load / Traffic Failures

Interview-focused · 12 failure types · autoscaling / rate limiting / backpressure · staff patterns

Core Mental Model — Generate Any Load Failure From This

Too many requests → surge / overload / herd Uneven requests → hotspot / hot partition Bursty requests → spiky load / retry amplification Slow consumers → queue backlog / backpressure

Most real outages are load/traffic problems, not code bugs. A small set with clear reasoning covers everything.

1 Traffic Spike / Sudden Surge
WhatSudden increase in requests — viral event, flash sale, breaking news
System capacity < incoming traffic
2 Sustained High Load (Overload)
WhatContinuous traffic that exceeds system capacity for an extended period
System cannot keep up for long duration
3 Thundering Herd Classic
WhatMany clients hit the system at the same instant — typically post-cache-expiry or post-outage
ExampleCache TTL expires — all requests simultaneously hit the DB
Sudden synchronized traffic burst
→ DB or origin overwhelmed
4 Hotspot / Hot Key / Hot Partition Classic
WhatUneven traffic — one entity attracts massively disproportionate load
ExampleOne celebrity post / product / DB shard gets all the traffic
One node overloaded, others idle
→ horizontal scale doesn't help
5 Cache Stampede
WhatCache miss causes many concurrent requests to all hit the backend simultaneously
ExamplePopular cache key expires — 10,000 threads race to rebuild it from DB
Cache failure → DB overload
6 Queue Overload / Backlog
WhatProducers enqueue faster than consumers can process
ExampleOrder events pile up while payment service is slow
Queue grows uncontrollably
→ memory exhaustion or data loss
7 Retry Amplification Dangerous
WhatFailed requests trigger retries — retries multiply the traffic load
Example10k clients each retry 3 times — 30k requests hit a struggling service
Retries multiply traffic
→ small failure becomes cascade
8 Thread / Connection Exhaustion
WhatToo many concurrent requests consume all available threads or connections
No capacity to serve new requests
→ queue or reject
9 Load Balancer Overload
WhatLB tier itself becomes the bottleneck and drops connections
Entry point becomes the bottleneck
→ traffic never reaches services
10 Slow Consumer / Backpressure Failure
WhatDownstream is slower than upstream — pressure builds upstream
ExampleDB writes slow down → API layer accumulates open connections
Processing rate < arrival rate
→ upstream overloads
11 Burst Traffic (Spiky Load)
WhatShort, sharp traffic spikes — system unstable between bursts and idle
System thrashes between
overload and underuse
12 Cascading Load Failure Most Dangerous
WhatOne overloaded service slows others — failure propagates through the system
Failure spreads across system
→ full outage from one overloaded node

5-Bucket Memory Model — Use This in Interviews

Load failures = 1. Too much traffic → spike / sustained overload 2. Uneven traffic → hotspot / hot partition 3. Sudden traffic → thundering herd / cache stampede 4. Repeated traffic → retry amplification 5. Slow processing → queue backlog / backpressure

Final truth: incoming rate > processing capacity. Your job is to either increase capacity or reduce / shape traffic.

Staff Pattern — Use Every Time

Detect → Mitigate → Prevent

1. Traffic Spike / Sudden Surge

Detect via RPS spike / queue depth / error rate
→ autoscaling + CDN for static reads
→ pre-scale for known events (sales, launches)
→ Prevent with capacity planning + load testing

2. Sustained High Load (Overload)

Detect via sustained high CPU / latency / queue
→ scale horizontally + offload to async workers
→ separate read and write paths
→ Prevent via capacity planning + load testing

3. Thundering Herd

Detect via synchronized spike after cache expiry
→ request coalescing (single-flight pattern)
  + jittered retries to desynchronise clients
→ Prevent with staggered TTLs + cache locking

4. Hotspot / Hot Key / Hot Partition

Detect via uneven shard / node metrics
→ spread load: consistent hashing with
  virtual nodes, or local caching of hot keys
→ Prevent with better shard keys
  or dynamic rebalancing

5. Cache Stampede

Detect via cache miss spike + DB QPS surge
→ cache-aside with mutex / single-flight lock
  (only one thread rebuilds, others wait)
→ Prevent with pre-warming + staggered TTLs
  + soft expiry / probabilistic refresh

6. Queue Overload / Backlog

Detect via queue lag / growing backlog metrics
→ scale consumers + prioritise critical jobs
  + dead-letter queue for overflow
→ Prevent with backpressure on producers
  and consumer autoscaling

7. Retry Amplification

Detect via surge in retry traffic / error rate
→ circuit breaker to stop retries when open
  + exponential backoff with jitter
  + cap max retries
→ Prevent with idempotent APIs + retry budgets

8. Thread / Connection Exhaustion

Detect via pool exhaustion / high wait time
→ rate limiting + request queuing
  + increase pool size cautiously
→ Prevent with async / non-blocking IO
  and connection pooling

9. Load Balancer Overload

Detect via LB saturation / dropped connections
→ multiple LBs + anycast / DNS load spreading
  + health-check backends + remove sick nodes
→ Prevent by scaling LB tier ahead of demand

10. Slow Consumer / Backpressure Failure

Detect via queue lag + increasing upstream latency
→ backpressure: throttle producers to match
  consumer rate + buffer with bounded queues
→ Prevent with consumer autoscaling
  and isolating slow processing paths

11. Burst Traffic (Spiky Load)

Detect via short-lived RPS spikes
→ buffering with queues + token buckets
  + burst-friendly autoscaling policies
→ Prevent with request smoothing:
  rate limiting + traffic shaping

12. Cascading Load Failure

Detect via multi-service latency / error spikes
→ circuit breakers + bulkheads to contain blast
  + load shedding (drop non-critical traffic)
→ Prevent by isolating services with
  timeouts + bulkheads + async decoupling

5 Core Load Mitigation Patterns — Everything Maps Here

1. Scale → autoscale, add replicas, shard better 2. Throttle → rate limit, backpressure, token bucket 3. Buffer → queues, bounded buffers, async decoupling 4. Cache → CDN, local cache, pre-warm, single-flight 5. Isolate → circuit breaker, bulkhead, load shedding

Staff-Level One-Liner

"I would detect load issues via RPS and latency metrics, scale horizontally, throttle excess traffic using rate limiting and backpressure, buffer with queues, cache hot paths using CDN and single-flight, and isolate failures using circuit breakers and load shedding."
