Infrastructure-Level Failure Scenarios

Staff-level · 26 scenarios · detect / mitigate / prevent / cascading / trade-off

Foundation Layer

Compute + Storage + Network + Power + Region

Infrastructure failures affect everything above them. Slow failures are often more dangerous than hard failures — they trigger retries and create cascading overload before anyone detects them.

8 Must-Know Infrastructure Failures for Interviews

1. Node crash → replicas + auto-restart + LB health checks 2. CPU / Memory exhaustion → horizontal scale + limits + async 3. Disk failure → RAID + replication + backups 4. Network failure → redundancy + circuit breaker 5. Data center outage → multi-AZ / multi-region active-active 6. Load balancer failure → HA LB + health checks 7. Bandwidth saturation → CDN + traffic shaping + compression 8. Replica rebuild overload → throttle rebuild IO + prioritise reads

Staff-Level Infrastructure Thinking — 5 Questions to Ask Always

1. Is it isolated or widespread? → single node vs rack vs AZ vs region 2. Is it a hard failure or slow failure? → hard: immediate | slow: insidious (triggers retries) 3. Can traffic fail over safely? → is healthy capacity available to absorb it? 4. Can retries overload healthy systems? → are circuit breakers and rate limits in place? 5. How quickly can the system recover? → minutes (restart) vs hours (rebuild replica) vs days (restore backup)

Hard vs Slow Failure — Why Slow Is More Dangerous

Hard Failure

  • Node immediately unreachable
  • Health check fails instantly
  • LB removes node quickly
  • Impact: fast and visible

Slow Failure (More Dangerous)

  • Node responds but very slowly
  • Health check still passes
  • Callers wait, holding threads
  • Retries amplify the load
  • Impact: slow, insidious, cascading

Practice Framework — Apply to Any System in Interviews

For ANY system, walk through these: 1. What infra components exist? → servers, LB, DB, cache, queue, network, storage 2. What if one crashes (hard failure)? → who detects it? where does traffic go? is capacity enough? 3. What if one becomes slow (soft failure)? → timeouts set? circuit breaker present? retries bounded? 4. How does traffic fail over? → LB health checks? DNS failover? active-active? 5. Can retries create a cascade? → backoff + jitter? circuit breaker? rate limit?
