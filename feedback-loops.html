Feedback & Amplification Loops

Retry storms, cascading failure — Tier-1 Staff/Principal Engineer topic

⭐ Tier-1 Staff / Principal Engineer Topic

How Interviewers Actually Ask This

Interviewers won't ask "Explain feedback loops." They ask:

  • Why did the outage spread?
  • Why didn't retries help?
  • Why did autoscaling make things worse?
  • How would you prevent cascading failures?
  • What happens when one dependency becomes slow?
  • Why did CPU suddenly spike after a database slowdown?

These are all feedback loop questions.

Definition

Feedback loops occur when a system's output becomes its own future input. Some loops stabilize the system, while others amplify failures until the entire system collapses.

Why Should You Learn This?

Almost every large-scale production outage is caused by an amplification loop, not a single bug.

Retry Storm Cache Stampede Cascading Failure Thundering Herd Autoscaling Thrashing

Core Mental Model

System ↓ Failure ↓ System Reacts ↓ Reaction Changes System ↓ More Failure OR Recovery

Two Types of Feedback Loops

TypeEffectGoal

🟢 Negative Feedback Loop (Good)

The system automatically reduces instability.

CPU ↑ ↓ Auto Scaling ↓ More Pods ↓ CPU ↓

Examples

Auto Scaling Rate Limiter Circuit Breaker Backpressure Load Balancer TCP Congestion Control
Golden Rule: Problem → System Corrects It → System Stable

🔴 Positive Feedback Loop (Bad)

The system reacts in a way that increases the problem.

Database Slow ↓ Timeout ↓ Retry ↓ More Database Load ↓ Database Slower ↓ More Retries ↓ Database Crash
Golden Rule: Problem → Reaction → Bigger Problem → More Reaction

1️⃣ Retry Storm

Clients continuously retry failed requests.

Database Slow ↓ Timeout ↓ 1000 Clients Retry ↓ Database Load Doubles ↓ More Timeout ↓ More Retry ↓ Complete Outage

Symptoms

  • RPS suddenly doubles
  • CPU spikes
  • Timeout increases
  • Retry count explodes

Fix

  • Exponential Backoff
  • Jitter
  • Circuit Breaker
  • Retry Budget
  • Request Timeout

Seen at: AWS · Google · Netflix

2️⃣ Cascading Failure

Failure spreads from one service to others. Every dependency waits for another — eventually everything becomes blocked.

Database Slow ↓ API waits ↓ Thread Pool Full ↓ Gateway waits ↓ Users Timeout ↓ Retries ↓ Entire System Down

Detect

  • Thread Pool Full
  • Queue Growth
  • Connection Pool Exhausted
  • High Latency / Timeouts

Fix

  • Bulkheads
  • Timeouts
  • Circuit Breakers
  • Async Messaging
  • Fail Fast

3️⃣ Cache Stampede

Thousands of requests miss the same cache key simultaneously.

Cache Expires ↓ 10000 Requests ↓ Database ↓ CPU 100% ↓ Database Slow
Request Collapsing Refresh Ahead TTL Randomization Single Flight

4️⃣ Thundering Herd

Many clients wake up simultaneously and hit the same resource.

Cache Refresh ↓ 10000 Pods ↓ Same Database ↓ Database Crash
Jitter Random Delay Distributed Lock

5️⃣ Autoscaling Thrashing

Autoscaler continuously scales up and down, causing instability and cold starts.

Traffic Spike ↓ Scale Up ↓ Traffic Drops ↓ Scale Down ↓ Traffic Returns ↓ Scale Up Again
Cooldown Period Hysteresis Predictive Scaling

Staff Engineer Checklist

Before approving any design, ask:

  • ✅ What happens if one dependency becomes slow?
  • ✅ Can retries amplify the outage?
  • ✅ Can failures spread to other services?
  • ✅ Where are the feedback loops?
  • ✅ Do we have circuit breakers?
  • ✅ Are retries bounded?
  • ✅ Can queues grow indefinitely?
  • ✅ Will autoscaling stabilize or amplify the problem?
  • ✅ Can one failure become a system-wide outage?

Interview Cheat Sheet

Negative Feedback (Stabilizing) • Auto Scaling • Rate Limiting • Circuit Breaker • Backpressure Positive Feedback (Amplifying) • Retry Storm • Cache Stampede • Cascading Failure • Thundering Herd • Autoscaling Thrashing Golden Rule Every automatic reaction should REDUCE failure, not amplify it.

⭐ Principal Engineer Takeaway

A Principal Engineer doesn't ask "How do I fix this failure?" They ask:

  • What automatic reactions will this failure trigger?
  • Will those reactions stabilize the system or amplify the outage?
  • Where can I insert isolation, backpressure, or circuit breakers to stop the failure from propagating?

The most dangerous failures in distributed systems are rarely the initial fault — they're the feedback loops that amplify it into a full-scale outage.
