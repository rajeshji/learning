Network Latency Sources

Serialization · Propagation · Queuing · Processing — where latency actually comes from

The Big Picture

When a request feels "slow," it is rarely one reason. Network latency is the sum of multiple delays as data travels from one machine to another. Total Latency = Serialization + Propagation + Queuing + Processing. Each component dominates in a different environment.

Client │ Serialization Delay (packet placed on wire) ▼ ══════════════════════ Wire ══════════════════════ │ Propagation Delay (bits travel at ~2/3 light speed) ▼ Router / Switch │ Queuing Delay (waits in buffer) ▼ Server NIC │ Processing Delay (decrypt, route, forward) ▼ Application

1 — Serialization Delay

Time to place every bit of a packet onto the wire (filling the pipe).

Delay = Packet Size (bits) / Bandwidth (bps) 1500 B packet @ 1 Gbps → ~12 µs 1500 B packet @ 100 Mbps → ~120 µs 1500 B packet @ 1 Mbps → ~12 ms

Reduce by:

  • Compress payloads (gzip, Brotli)
  • Use Protobuf instead of JSON
  • Batch multiple requests
  • Jumbo Frames in datacenters
  • Remove unnecessary metadata

Dominates on: mobile, IoT, large payloads, slow WAN links.

2 — Propagation Delay

Time for the first bit to physically travel across the medium. Limited by speed of light — cannot be eliminated.

Delay = Distance / Signal Speed Signal speed: fiber ~200,000 km/s Same rack (100m) → ~0.5 µs City (200 km) → ~1 ms India → US → ~70–80 ms one-way GEO satellite → ~120 ms one-way

Reduce by:

  • CDN / Edge Computing
  • Regional replicas
  • Local caches
  • Fewer round trips (0-RTT, QUIC)
  • Connection reuse

Dominates on: cross-region, global services.

3 — Queuing Delay

Time a packet waits in a buffer before being transmitted. The main cause of jitter and high P99 latency.

Delay ≈ Queue Size / Bandwidth Router buffer 1 MB @ 1 Gbps → ~8 ms wait! Causes: congestion, burst traffic, bufferbloat, slow downstream, overloaded LB

Reduce by:

  • Backpressure
  • Active Queue Management (CoDel, RED)
  • BBR congestion control
  • Rate limiting
  • Autoscaling
  • Load balancing + reduce fan-out

Dominates on: high QPS backends, congested networks, mobile.

4 — Processing Delay

Time devices spend examining, routing, decrypting, and forwarding. Accumulates at every hop.

Simple switch → 1–5 µs Router → 10–100 µs TLS termination → 1–5 ms Service mesh → 0.5–2 ms API gateway → 1–10 ms Multiple proxies can add 5–20ms inside a datacenter!

Reduce by:

  • Async I/O, io_uring
  • Zero-copy networking
  • TLS offloading to hardware
  • Kernel bypass (DPDK)
  • Reduce proxy chain depth

Dominates on: same-rack, TLS-heavy, multi-proxy paths.

  • Is propagation irreducible (speed-of-light limit)?
  • Is P99 driven by queuing bursts or retransmits?
  • What is our latency budget per tier?
  • How many proxy hops are adding processing delay?
  • Is TLS handshake cost measured and cached?
  • How do we model cross-region latency in SLO budgets?

Key Takeaways

Total Latency = Serialization + Propagation + Queuing + Processing Serialization: = Packet Size / Bandwidth Optimize: compression, Protobuf, batching, Jumbo Frames Dominates: mobile, IoT, large payloads Propagation: = Distance / Speed of Light (~2/3c in fiber) CANNOT be eliminated — reduce distance instead Optimize: CDN, edge, regional replicas, fewer RTTs Dominates: cross-region, global Queuing: ≈ Queue Size / Bandwidth Main driver of tail latency (P99/P999) and jitter Optimize: backpressure, BBR, CoDel, autoscaling Dominates: high-QPS, congested networks Processing: Every hop adds: TLS 1–5ms, service mesh 0.5–2ms, etc. Optimize: async I/O, TLS offload, zero-copy, fewer proxies Dominates: same-rack, TLS-heavy, multi-proxy paths Staff mindset: 1. Identify dominant source 2. Quantify its impact 3. Propose targeted mitigation 4. Discuss trade-offs 5. Tie back to latency budget + SLOs
