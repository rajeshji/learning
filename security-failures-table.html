Why Security Failures Are Uniquely High Severity

Security affects: confidentiality + integrity + availability + trust Unlike outages: security failures may silently persist for months 9 root failure classes: authentication | authorization | data exposure | encryption API/network attacks | injection | availability attacks | infrastructure | org
Failure Scenario When It Occurs How To Detect How To Mitigate How To Prevent Cascading Failure Risk Trade-off
1 — Authentication Failures
Credential StuffingMust Know Attackers use leaked username/password lists to authenticate at scale Login anomaly spike from many IPs, high fail-then-succeed pattern Rate limit per IP, force MFA for suspicious login patterns Enforce MFA, breach password detection (HaveIBeenPwned integration) Auth service overload, mass account takeovers across user base Aggressive rate limiting adds friction for legitimate users
Brute Force Attack Repeated automated password attempts against single or multiple accounts Failed login surge, same account or same IP repeated attempts Account lock after N failures, CAPTCHA after threshold Adaptive rate limiting, account lockout policy, anomaly-based detection Legitimate user lockouts, auth service resource exhaustion Account lockout can be weaponised to lock out real users (DoS via lockout)
JWT Token Forgery / CompromiseMust Know Weak signing secret leaked or attacker uses alg:none bypass Anomalous token signatures, invalid-format tokens being accepted Rotate signing keys immediately, invalidate all outstanding tokens Strong signing algorithms (RS256/ES256), reject alg:none, short TTL Unauthorized access to entire platform for all token holders Short JWT TTL increases refresh frequency and auth service load
Session HijackingMust Know Session token stolen via XSS, network sniffing, or log leakage Suspicious session reuse from different IP, device, or geography Revoke stolen session, force re-authentication Secure HttpOnly + SameSite cookies, HTTPS everywhere, short session TTL Account takeover — attacker acts as victim with full session privileges Short session TTL degrades UX; frequent re-auth frustrates users
MFA BypassMust Know Logic flaw, social engineering (SIM swap), or code reuse vulnerability Successful auth despite expected MFA failure, login from new device without MFA Force re-authentication, disable compromised MFA method Strong MFA enforcement (TOTP/WebAuthn), anti-SIM-swap controls Privilege escalation — full account access without valid second factor Stronger MFA (hardware keys) adds user friction and support burden
2 — Authorization and Access Control Failures
Privilege EscalationMust Know RBAC/ACL flaw allows low-privilege user to gain admin or elevated access Unexpected admin actions by non-admin user, RBAC audit anomaly Revoke elevated access immediately, audit all actions taken Principle of least privilege, RBAC with regular access reviews System-wide compromise — attacker with admin access can do anything Strict least-privilege requires more complex permission management
Broken Access ControlMust Know API endpoint missing authorization check — any authenticated user can access Unauthorized resource access in logs, security scanner finding Patch endpoint immediately, add centralised auth middleware Centralised authorization middleware, not per-endpoint manual checks Data leakage — any authenticated user reads/modifies any resource Centralised auth adds latency; overly strict auth may block valid flows
IDOR (Insecure Direct Object Reference)Must Know Predictable resource IDs (user?id=123 → user?id=124) allow cross-user access Suspicious enumeration pattern, audit of resource access across user IDs Validate resource ownership on every access, reject unauthorized access Object-level authorization on every endpoint, use non-guessable UUIDs Cross-user data exposure at scale — all objects enumerable Per-object auth checks add latency; UUIDs complicate debugging
Tenant Isolation FailureMust Know Multi-tenant boundary bug — one tenant accesses another tenant's data Cross-tenant data access in audit logs, tenant-scoped data mismatch Isolate affected tenant traffic, patch isolation layer Strong tenant ID enforcement at DB and API layer, separate schemas/DBs SaaS-wide exposure — all tenants potentially affected by isolation breach Stronger isolation (separate schemas) costs more and complicates ops
Policy Misconfiguration Incorrect IAM/RBAC rules pushed — too permissive or too restrictive Unexpected permission grants, security alert on overpermissioned access Rollback policies immediately, audit all access since misconfiguration Policy testing in staging, least-privilege by default, policy-as-code Broad system exposure if too permissive; lockout if too restrictive Restrictive policy testing slows feature delivery
3 — Data Exposure and Leakage Failures
PII Data LeakMust Know Logs, API responses, or error messages expose personally identifiable information DLP alerts, sensitive field detected in log stream or API response body Sanitize logs immediately, mask or remove PII from affected fields Data masking, tokenisation, structured secure logging, DLP in pipeline Compliance/legal impact — GDPR/CCPA fines, customer trust damage Masking PII reduces debugging information available to engineers
Database / Storage Dump ExposureMust Know Misconfigured S3 bucket, public storage ACL, or unprotected DB endpoint Public access detection alert, unexpected external connection to storage Revoke public access immediately, rotate credentials Private-by-default storage policy, automated public-access detection scanning Massive data breach — entire database or backup exposed publicly Strict access controls reduce flexibility for legitimate cross-team sharing
Sensitive Data in Logs Tokens, passwords, or API keys accidentally logged by application code Secret scanning in log pipeline, grep for known secret patterns Rotate all leaked credentials, sanitize log pipeline Structured logging policy, secret scanning in CI, never log auth headers Credential compromise — anyone with log access has valid secrets Strict logging policy reduces debug detail available during incidents
Backup Exposure Unencrypted backup stored in accessible location, or backup uploaded to wrong target Access anomaly on backup storage, unexpected download of backup file Revoke access, rotate exposed credentials, notify affected users Encrypt all backups at rest, private-by-default backup storage Long-term data compromise — attacker has full point-in-time snapshot Encryption adds backup storage overhead and restore complexity
4 — Encryption and Key Management Failures
TLS Certificate ExpiryMust Know Certificate not renewed in time — clients reject connection with SSL error TLS handshake failures, browser/client certificate error, monitoring alert Emergency certificate renewal, hot-swap cert without downtime Automated renewal (Let's Encrypt/ACM), cert expiry monitoring with 30-day alert Entire HTTPS service unavailable — all clients see SSL error Automated rotation adds complexity; rotation itself can briefly fail
Secret / Key LeakageMust Know API keys, DB passwords, or signing keys committed to git or embedded in logs Secret scanning alert (git-secrets, Trufflehog), SIEM alert Rotate leaked keys immediately, revoke old keys Vault/KMS for all secrets, secret scanning in pre-commit hooks and CI System-wide compromise — attacker has valid credentials for all services Secret management systems add operational overhead and access latency
Improper Key Rotation New key deployed without overlap period — services using old key fail to decrypt Decryption failures, auth errors across services after rotation Support both old and new key temporarily (graceful dual-key period) Automated key rotation with dual-key overlap, rotation testing in staging Service-wide failures — all data encrypted with old key becomes unreadable Dual-key support increases key management complexity
Hardcoded Credentials Secrets embedded directly in source code or config files committed to repo Repository scanning (Trufflehog, GitGuardian), found in code review Rotate credentials immediately, remove from code, purge from git history Secret management systems (Vault/AWS Secrets Manager), pre-commit scanning Credential compromise — anyone with repo access has valid production secrets Secret management requires developer workflow changes and tooling investment
5 — API and Network Security Failures
DDoS AttackMust Know Massive malicious traffic floods infrastructure — volumetric or application-layer Traffic spike anomalies, infrastructure saturation, unusually high request rates Traffic scrubbing, CDN absorb, block at upstream (BGP blackholing) DDoS protection (AWS Shield/Cloudflare), anycast routing, WAF Entire service unavailable — legitimate traffic blocked alongside attack DDoS protection adds cost; traffic scrubbing can cause false positives
API Abuse / Scraping Automated bots make excessive requests — scrapers, credential stuffing, abuse Unusual API usage patterns, high request volume from single client/IP range Rate limiting, block abusive client, apply WAF rules API quotas per client, bot detection, device fingerprinting Backend overload — legitimate traffic starved by abusive bots Aggressive bot detection may block legitimate automated clients
SSRF (Server-Side Request Forgery)Must Know Attacker tricks backend into making HTTP request to internal or cloud metadata URL Suspicious outbound traffic to 169.254.169.254 or internal addresses Block access to internal IP ranges and metadata endpoints immediately URL allowlists (not denylists), IMDSv2, egress firewall rules Cloud credential theft — attacker retrieves IAM tokens from metadata service Strict URL allowlisting may break valid integrations that weren't anticipated
DNS Hijacking DNS record compromised — attacker redirects traffic to malicious server Unexpected DNS resolution, traffic anomalies, certificate mismatch Switch to trusted DNS provider, enable DNSSEC DNSSEC validation, registrar account MFA, DNS monitoring for record changes Traffic interception at scale — all users communicate with attacker's server DNSSEC adds DNS resolution complexity and can fail if misconfigured
MITM Attack Attacker intercepts traffic on insecure network — captures credentials or tokens TLS anomalies, certificate pinning failure, unexpected cert issuer Force HTTPS everywhere, implement certificate pinning on mobile TLS everywhere (including internal), HSTS, certificate pinning Credential theft at scale — all traffic on compromised network captured Certificate pinning breaks on cert rotation; HSTS can lock out on misconfiguration
6 — Injection and Application Exploit Failures
SQL InjectionMust Know User input directly concatenated into SQL query without sanitisation Suspicious DB queries in logs, WAF alert on SQL keywords in input Block offending request, patch vulnerable endpoint Parameterised queries (prepared statements) everywhere, ORM usage Full DB compromise — attacker can read, modify, or delete all data ORMs can hide query details, making complex query tuning harder
Command Injection User input passed directly to shell command — attacker executes arbitrary commands Abnormal process execution, unexpected child processes spawned by service Disable vulnerable endpoint, kill malicious processes Never use shell with user input, input sanitization, process sandboxing Host compromise — attacker has shell access to application server Sandboxing processes reduces runtime flexibility for legitimate operations
XSS (Cross-Site Scripting)Must Know Attacker injects script into page that executes in victim's browser context CSP violation reports, browser security alerts, unexpected script execution Sanitize output immediately, force CSP headers Output escaping, Content Security Policy, modern frameworks with auto-escaping Session theft and account takeover at scale for all affected page visitors Strict CSP may break legitimate third-party scripts and integrations
Deserialization Attack Attacker sends malicious serialized object — deserializer executes embedded code Unusual object patterns, unexpected class instantiation in logs Disable vulnerable endpoint, block malicious payloads at WAF Use safe data formats (JSON over Java serialization), type allowlisting Remote code execution — attacker can run arbitrary code on server Removing native serialization requires significant code migration effort
7 — Availability and Resource Exhaustion Attacks
Application-Layer DDoSMust Know Expensive API endpoints targeted — attackers trigger resource-intensive operations CPU/latency spike on specific endpoints, WAF anomaly detection WAF rate limiting, disable expensive endpoint temporarily Request cost control (timeouts, pagination), auth before expensive operations Backend overload — expensive ops exhaust CPU/DB, blocking all other requests Auth-before-expensive may block unauthenticated public API use cases
Slowloris Attack Attacker holds many HTTP connections open sending headers slowly — exhausts connections Connection count at maximum, legitimate requests queuing or refused Apply aggressive idle connection timeout, kill slow connections Connection timeout limits, reverse proxy with connection management (Nginx) Gateway/LB connection exhaustion — legitimate clients cannot connect Short idle timeouts may disconnect legitimate slow clients or mobile users
Cache Poisoning Attack Attacker crafts request that causes malicious response to be cached globally Unexpected/invalid cached content, users reporting wrong data globally Flush affected cache keys, block attack vector Cache key normalisation, avoid caching responses with attacker-controlled headers Wrong data served globally to all users hitting poisoned cache entries Restrictive cache key rules reduce cache hit rate and increase origin load
Queue Flooding Attack Attacker floods message queue with fake events, overwhelming consumers Queue depth explosion, consumer lag growing rapidly, legitimate events delayed Drop/throttle traffic, apply per-sender rate limits at queue ingress Authentication before enqueue, producer rate limits, message validation MQ collapse — legitimate events drowned by fake events, consumers stall Auth before enqueue adds latency to every message ingestion path
8 — Infrastructure and Cloud Security Failures
Public Cloud Bucket ExposureMust Know Storage bucket ACL misconfigured as public — anyone on internet can download Cloud provider public access alert, scanner detecting public bucket Revoke public access immediately, audit what was downloaded Private-by-default storage policy, automated misconfiguration scanning (CSPM) Massive data breach — potentially millions of records publicly downloadable Strict private-by-default requires explicit sharing flows that add ops overhead
Container Escape Container runtime or kernel vulnerability allows attacker to break out to host Suspicious host-level activity from container process, anomaly detection Isolate affected node, rebuild from clean image Container sandboxing (gVisor/Kata), non-root containers, minimal base images Cluster-wide compromise — host access means access to all containers on node Sandboxing adds performance overhead; restrictive containers limit flexibility
Kubernetes RBAC Misconfiguration Overpermissive ClusterRole — attacker with pod access can escalate to cluster admin Unexpected RBAC access, privilege audit anomaly in cluster Remove overpermissive bindings, rotate compromised service account tokens Minimal RBAC (no cluster-admin), regular RBAC audits, RBAC-as-code Full cluster compromise — attacker can read all secrets, deploy malicious workloads Minimal RBAC requires careful per-workload permission design
Cloud Metadata Service Exposure (SSRF) SSRF vulnerability used to fetch IAM tokens from 169.254.169.254 Unexpected requests to metadata service IP, IAM token anomaly Revoke compromised IAM credentials immediately IMDSv2 (requires PUT hop before GET), block 169.254.169.254 via egress firewall Cloud credential theft — attacker has IAM access to all cloud resources IMDSv2 breaks older EC2 SDKs that don't support hop-limit requirement
9 — Detection, Response, and Organizational Failures
Audit Logging FailureMust Know Security-relevant events not logged — pipeline failure, disk full, misconfiguration Log gap detection, audit pipeline health check, missing expected events Restore logging pipeline, reconstruct events from alternative sources Redundant audit log pipeline, immutable log storage, log completeness monitoring Undetected compromise — attacker operates undetected during log gap Redundant logging adds storage cost; immutable logs are harder to manage
Incident Response Failure Slow or ineffective response to detected breach — lack of runbooks or tooling Long mean-time-to-contain metric, breach scope expanding during response Emergency isolation of affected systems, activate IR playbook IR playbooks, regular tabletop exercises, automated containment tooling Larger compromise scope — every hour of slow response the attacker goes deeper Aggressive isolation may cause availability disruption to unaffected systems
Supply Chain Attack Malicious dependency, compromised CI pipeline, or tampered container image Dependency scanning alert, unexpected binary in image, anomalous outbound traffic Roll back to pre-compromise version, rebuild from verified source Signed artifacts (SBOM), dependency pinning, supply chain security scanning Widespread compromise — malicious code shipped to all users of the package Strict dependency pinning slows security patches and updates
Insider Threat Malicious or negligent privileged user abuses their legitimate access Suspicious admin behavior, unusual data access volume, off-hours activity Revoke access immediately, preserve audit trail for forensics Least privilege, mandatory access reviews, behavioural anomaly detection Data destruction or leakage by trusted actor — hard to detect in real time Heavy monitoring of privileged users is privacy-sensitive and morale-affecting

10 Must-Know Security Failures for Interviews

1. Broken authentication → MFA + breach passwords + rate limiting 2. Broken access control → centralised auth middleware + least privilege 3. IDOR → object-level ownership check + non-guessable UUIDs 4. Secret/key leakage → Vault/KMS + secret scanning in CI + no hardcoding 5. SQL injection → parameterised queries + ORM + WAF 6. XSS → output escaping + CSP + auto-escaping frameworks 7. DDoS → CDN + WAF + DDoS protection + anycast 8. Tenant isolation failure → enforce tenant ID at DB + API layer + separate schemas 9. TLS cert expiry → automated renewal + 30-day expiry monitoring

Staff-Level Security Thinking — 9 Questions to Ask Always

1. Unauthorized data access? → object-level auth + tenant isolation + least privilege 2. Secrets/tokens leak? → Vault/KMS + scanning + rotation + no hardcoding 3. One tenant access another? → tenant ID at every layer + separate schemas 4. Attackers exhaust resources? → rate limits + WAF + auth before expensive ops 5. Auth dependency fail? → HA auth + cached JWT + fallback auth mode 6. Internal traffic intercepted? → mTLS + zero-trust + encrypt everything 7. Compromise detected quickly? → SIEM + audit logs + anomaly detection + IR drills

Common Security Cascading Failure Patterns

Root Security FailureCascading Effect
Credential stuffingMass account takeovers → auth service overload → legitimate logins fail
DDoS attackInfrastructure saturation → legitimate traffic blocked → full service outage
Secret leakageValid credentials stolen → all dependent services compromised
SQL injectionFull DB access → all user data breached → compliance/legal consequences
Tenant isolation failureCross-tenant access → SaaS-wide breach → regulatory action
Audit log failureCompromise undetected → attacker dwells longer → larger breach scope
TLS cert expiryAll HTTPS traffic fails → service unavailable → emergency response

Silent vs Noisy Failures — What Makes Security Unique

Noisy (infrastructure): crashes → immediate alert → fast response Silent (security): attacker persists → no alert → weeks/months undetected OWASP Top 10 silent patterns: Broken Access Control | Cryptographic Failures | Injection Insecure Design | Security Misconfiguration Detection: SIEM + audit logs + anomaly detection + IR drills (infrastructure monitoring alone is NOT enough)

Final Mental Model — All Security Failures Reduce to 5 States

1. Identity compromised → auth fail / credential leak / token forgery 2. Access control broken → privilege escalation / IDOR / tenant isolation 3. Data exposed → PII leak / bucket exposure / sensitive logs 4. Traffic abused → DDoS / SSRF / injection / API abuse 5. Detection failed → audit log gap / slow IR / no anomaly detection Silent compromise + detection failure = worst combo dwell time grows → scope grows → recovery catastrophically expensive
