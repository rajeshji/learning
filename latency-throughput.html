Latency, Throughput, Concurrency & Utilization

Interview notes — Senior / Staff Engineer level

Core Idea

Performance is not about optimizing one metric. Great systems balance Latency, Throughput, Concurrency, and Utilization based on business requirements.

Why Learn This? — Every Interview Asks These

Why is the system slow? Why can't it handle more users? Latency vs Throughput? When should we scale? CPU 60% but latency high?

The Four Performance Metrics

MetricDefinitionGoalUnit
LatencyTime to complete one requestLowerms, sec
ThroughputWork completed per unit timeHigherRPS, TPS, MB/s
ConcurrencyOperations executing simultaneouslyHigher (within limits)Threads, Connections

Trade-offs

OptimizeBenefitTrade-off
Low LatencyBetter UXLower throughput, higher infra cost
High ThroughputMore work/secHigher latency under load
High ConcurrencyMore simultaneous usersMore contention + memory usage
High UtilizationBetter cost efficiencyRisk of overload & latency spikes

How They Relate — The Saturation Chain

More Concurrency ↓ Higher Throughput ↓ Higher CPU Utilization ↓ System Saturation ↓ Latency Increases ↓ Timeouts & Errors

The key is finding the sweet spot before saturation.

Real-World Example — Flash Sale

What Happens

Traffic Spike ↓ Concurrency ↑ ↓ Throughput ↑ ↓ CPU Utilization 95% ↓ Latency Increases ↓ Checkout Slows

Solutions

  • Read Replicas

  • Circuit Breakers

Common Interview Mistakes

✕ Optimizing CPU to 100%

✕ Increasing concurrency before removing bottlenecks

✕ Focusing only on throughput

✕ Ignoring P95/P99 latency

✕ Scaling before identifying the bottleneck

Staff Engineer Mindset

"How do I reduce latency?"

✓ Which metric is the actual bottleneck?

✓ Can I improve throughput without hurting latency?

✓ Is utilization approaching saturation?

✓ Will increasing concurrency improve capacity or create contention?

✓ What is the business priority: fast response or high throughput?

Golden Rules

  • Lower latency improves user experience.
  • Higher throughput improves scalability.
  • Concurrency increases capacity, but too much causes contention.
  • Keep utilization high, but leave headroom for traffic spikes.
  • Always optimize the bottleneck, not the busiest component.
  • Measure P95/P99 latency, not just averages.

Interview Cheat Sheet

Latency │ Network, Database, Cache, Processing, P95/P99 Throughput │ Requests/sec, TPS, Messages/sec, MB/sec Concurrency │ Users, Threads, Connections, DB Transactions Utilization │ CPU %, Memory %, Disk %, Network %, Queue % Golden Rule: Don't optimize one metric in isolation. Balance all four based on business requirements. Measure → Analyze → Optimize → Validate

Interview One-Liner

Latency is how fast one request completes, throughput is how much work is completed, concurrency is how many requests run simultaneously, and utilization is how busy the system resources are. Great distributed systems balance all four metrics instead of optimizing only one.
