RAID Levels (0/1/5/6/10) & Trade-offs

Striping, mirroring, parity, rebuild risk — Staff Engineer level

The Big Picture

A single disk is a single point of failure. RAID combines multiple disks using striping, mirroring, and parity to improve performance, availability, and reliability simultaneously.

Striping Mirroring Parity RAID 0 RAID 1 RAID 5 RAID 6 RAID 10 Rebuild

Three RAID Building Blocks

Striping

File → split Disk1 → Block A Disk2 → Block B Disk3 → Block C

Parallel I/O. Higher throughput. No redundancy.

Mirroring

Disk1 → Data Disk2 → Copy (identical)

Immediate redundancy. Fast recovery. 50% capacity.

Parity

A XOR B = P If B fails: B = A XOR P

Reconstruct lost data. Better efficiency than mirror. CPU overhead.

RAID 0 — Pure Striping

File → Disk1:A / Disk2:B / Disk3:C / Disk4:D (reads/writes all disks in parallel) Capacity: 100% of total disks

Strengths

  • Fastest reads & writes
  • 100% usable capacity

Weaknesses

  • Zero fault tolerance
  • One failure = total loss

Use for: Scratch space, rendering cache, temp data. Never for production databases.

RAID 1 — Mirroring

Disk1 ←→ Disk2 (identical mirror) Capacity: 50% Reads: from either disk (fast) Writes: to both (same speed as one disk)

Strengths

  • Excellent reliability
  • Fast, simple rebuild
  • Good read performance

Weaknesses

  • Only 50% capacity
  • Write speed = single disk

Use for: OS disks, DB transaction logs, critical metadata, small production DBs.

RAID 5 — Striping + Distributed Parity

Disk1 → Data A Disk2 → Data B Disk3 → Parity P (rotates) Capacity: (N-1)/N Min disks: 3 Survives: 1 disk failure

Strengths

  • Good read performance
  • Efficient storage utilization
  • Tolerates 1 disk failure

Weaknesses

  • Parity slows writes
  • Slow, risky rebuild
  • Rebuild risk ↑ with large disks

Use for: File servers, NAS, read-heavy workloads, backup repos.

RAID 6 — Striping + Double Parity

Disk1 → Data A Disk2 → Data B Disk3 → Parity P Disk4 → Parity Q (second parity) Capacity: (N-2)/N Survives: 2 disk failures

Strengths

  • Survives 2 simultaneous failures
  • Better protection for large arrays

Weaknesses

  • Slower writes (double parity)
  • Larger capacity overhead
  • Very slow rebuild

Use for: Large HDD arrays, enterprise storage, backup appliances, archives.

RAID 10 — Mirroring + Striping

Mirror Pair 1: Disk1 ↔ Disk2 Mirror Pair 2: Disk3 ↔ Disk4 ↓ stripe across pairs Capacity: 50% Survives: 1 disk per mirror pair

Strengths

  • Excellent read & write performance
  • Fast rebuild (only mirror pair)
  • High fault tolerance

Weaknesses

  • 50% storage efficiency
  • Higher hardware cost

Use for: OLTP databases, virtualization, financial systems, high-performance apps.

Rebuild Risk — Why It Matters

Modern HDDs are 16–20 TB. Rebuilding one disk reads every other surviving disk.

RAID 5 rebuild (16 TB HDD): • Duration: 20–40 hours • During rebuild: array runs slower • Another disk failure = TOTAL DATA LOSS RAID 10 rebuild: • Only the failed mirror pair rebuilds • Other pairs are unaffected • Much faster and safer

RAID 5 with large HDDs

High URE (unrecoverable read error) risk during rebuild. A single sector read error destroys the array. Use RAID 6 instead.

RAID 6 / RAID 10

RAID 6 survives a second failure during rebuild. RAID 10 rebuilds only its mirror pair — fast and low-risk.

Production Failure Scenarios

RAID 0 Total Loss

Cause: Single disk failure  ·  Fix: Never use RAID 0 for production data

RAID 5 Rebuild Failure

Cause: Second disk fails during 30-hour rebuild  ·  Fix: Use RAID 6 for large-capacity HDD arrays

Slow Database on RAID 5

Cause: Parity write overhead on write-heavy OLTP  ·  Fix: Move to RAID 10

Wasted Capacity on RAID 10

Cause: Using RAID 10 for archival storage (50% waste)  ·  Fix: Use RAID 6 or object storage for cold data

Modern Alternatives to Hardware RAID

TechnologyHow It Replaces RAID
ZFS RAIDZSoftware parity with checksums and self-healing

In cloud and distributed systems, software-defined replication scales better than hardware RAID. Hardware RAID is most relevant for on-prem servers.

Production Design Checklist

  • ✅ Identify workload: random vs sequential, read vs write ratio
  • ✅ Measure latency requirements (RAID 5/6 adds write latency)
  • ✅ Estimate rebuild duration based on disk size
  • ✅ Calculate usable capacity for each RAID level
  • ✅ Consider URE risk: use RAID 6 for HDDs > 4 TB
  • ✅ Evaluate hardware vs software RAID
  • ✅ Check if cloud storage already provides redundancy
  • ✅ Benchmark under production load before deploying

Key Takeaways

RAID 0 → Striping only. Fastest, zero tolerance. Scratch only. RAID 1 → Mirroring. Simple, reliable. 50% capacity. RAID 5 → Stripe+parity. Efficient, risky rebuild on large disks. RAID 6 → Double parity. Safer rebuild, more overhead. RAID 10 → Mirror+stripe. Best performance+resilience. 50% cap. Rebuild risk: Large HDD + RAID 5 = danger during 20–40h rebuild RAID 6 = survives second failure during rebuild RAID 10 = only mirror pair rebuilds (fast) Staff decision factors: Workload (OLTP vs NAS vs archive) Disk size (URE risk for RAID 5) RTO / rebuild time Capacity efficiency Hardware vs software-defined storage Cloud already provides redundancy?
